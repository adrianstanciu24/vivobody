# Remove in-app purchases

- Status: completed
- Outcome: a paid-upfront app with all existing features available immediately.
- Scope: remove purchase service/UI/configuration, all feature gates, widget
  entitlement preferences, and purchase-only verification paths. Preserve data,
  analytics eligibility, Apple Health authorization, and active-workout boundaries.
- Risk: stale gates in secondary surfaces or widget links. Keep snapshot payloads
  and SwiftData schema unchanged; old preference values become unused.
- Milestones: remove runtime gates; update active contracts and scenarios; run
  focused routing/settings/template tests, shared snapshot tests, inspected UI
  evidence in both appearances and large text, and `Scripts/check.sh`.
- Recovery: revert only this task's changes; preserve pre-existing recorder work.
- Manual boundary: setting the app price in App Store Connect is separate from
  repository changes. No external listing changes are authorized by this task.
- Result: removed the purchase owner, paywalls, Pro status/settings UI, product
  configuration, feature gates, and widget entitlement preferences. Insights and
  Exercise Detail render their original interactive instruments directly. Settings
  starts at Preferences. Template creation and batch saves have no purchase cap.
- Compatibility: preserved SwiftData and widget payload schemas, data-readiness
  rules, active-workout exploration restrictions, and HealthKit authorization.
  Old widget purchase URLs now open Insights; old purchase defaults are unused.
- Verification: working tree based on `43cf909`; `Scripts/check.sh` passed with
  the app/widget build, and `swift test --package-path VivoKit` passed all five
  current, legacy, obsolete, malformed, and missing-payload tests. The focused
  SettingsInteractionPolicyTests, IncomingActionTests, and StrengthRoutineSaveTests
  passed all 18 tests via headless `xcodebuild` with explicit `-only-testing` flags.
  All 11 scenario-runner Python tests passed. Logs: `.verify/paid-app-check.log`,
  `.verify/paid-app-vivokit.log`, `.verify/paid-app-tests.log`, and
  `.verify/paid-app-scenarios-tests.log`.
- UI evidence: all ten selected checked-in scenarios passed without purchase
  flags: `insights-showcase`, `insights-accessibility`,
  `insights-movement-coverage-light`, `exercise-comparison-unrestricted`,
  `exercise-detail-weekly-volume`, `exercise-detail-stamina` and its light and
  accessibility variants, `settings-preferences`, and
  `strength-routine-builder-unlimited-templates`. The final scenario saves three
  templates alongside three existing templates and verifies them after relaunch.
  Results, screenshots, and accessibility trees are in `.verify/scenarios/`.
- Visual review: inspected Insights and Exercise Detail in dark, light, and
  accessibility sizes. Inspected settled Settings captures in those states via
  three local `paid-app-settings-*` scenarios; their definitions are in
  `.verify/paid-app-scenarios/` and settled captures in `.verify/scenarios/`.
  Purchase controls are absent from the inspected trees; chart and comparison
  semantics remain exposed. Existing large-text navigation-title truncation is
  outside this gate-removal change; full exercise identity remains in semantics.
- Harness corrections: replaced historical locked scenarios, explicit Pro launch
  flags, stale Library-segment assumptions, and an offscreen-only assertion.
  Weekly-frequency copy now accepts the fixture's time-of-day rounding (1.6–1.7).
  The comparison scenario uses stable picker identifiers and follows the choice
  through to the comparison sheet. An initial test build hit Xcode's shared-build
  database lock; sequential build-for-testing/test-without-building passed.
- Manual gaps: physical-device VoiceOver traversal, HealthKit authorization/write,
  and installed Home/Lock Screen widget rendering were not exercised. Upfront
  pricing and any existing IAP listing cleanup in App Store Connect remain external
  release work; this task changed repository metadata only.
